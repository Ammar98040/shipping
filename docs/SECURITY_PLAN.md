# خطة الأمان — تنفيذ في المشروع

## ما تم تنفيذه

| البند | الوصف |
|--------|--------|
| **إعدادات الإنتاج** | عند `DEBUG=False`: إعادة توجيه HTTPS، كوكيز آمنة، HSTS، رؤوس أمان. |
| **كلمة المرور** | حد أدنى **10** أحرف + مدققات Django الافتراضية. |
| **تأكيد البريد** | التسجيل الحالي عبر OTP للبريد؛ حقل `email_verified_at` يُسجَّل عند إتمام التحقق. |
| **حد محاولات تسجيل الدخول** | عدّاد لكل (بوابة + مستخدم + IP)؛ قفل مؤقت بعد تجاوز الحد. |
| **Turnstile** | اختياري عبر `TURNSTILE_*` — تسجيل، تحقق OTP، نسيت كلمة المرور، وتسجيل دخول بعد فشل متكرر من نفس IP. |
| **حد معدل التسجيل** | لكل بريد + IP عند طلب OTP التسجيل (مشابه لإعادة تعيين كلمة المرور). |
| **تنبيه دخول (اختياري)** | `SEND_LOGIN_ALERT_EMAIL=True` يرسل بريداً بسيطاً عند نجاح دخول المتجر. |
| **تذكرني** | خانة اختيارية في دخول المتجر تمدد الجلسة. |

## متغيرات البيئة (`.env`)

انظر `.env.example` للقائمة الكاملة.

### Cloudflare Turnstile (مجاني)

1. لوحة Cloudflare → Turnstile → إنشاء موقع.
2. انسخ **Site Key** و **Secret Key** إلى `.env`.
3. بدون المفاتيح: في وضع التطوير (`DEBUG=True`) يُتخطّى التحقق. في **الإنتاج** (`DEBUG=False`) بدون مفاتيح لن يعمل **التسجيل** و**نسيت كلمة المرور** (يُرفض الطلب) — عيّن المفاتيح أو شغّل مؤقتاً بتطوير على HTTPS تجريبي.

### مفاتيح حد الدخول (اختياري)

- `LOGIN_FAILURE_MAX` — عدد المحاولات قبل القفل (افتراضي 5).
- `LOGIN_FAILURE_LOCK_SECONDS` — مدة القفل بالثواني (افتراضي 900).
- `LOGIN_CAPTCHA_AFTER_FAILS` — بعد كم فشل من نفس IP تُطلب Turnstile (افتراضي 3).

## اختبارات تلقائية

```bash
python manage.py test store.tests
```

- `store/tests/test_security.py` — حد الدخول وTurnstile.
- `store/tests/test_flows.py` — نسيت كلمة المرور (متجر + إدارة)، تسجيل + OTP، صلاحيات الشحن.

## Webhooks الوهمية (تطوير / اختبار)

- المسارات تستخدم `@csrf_exempt` لأن المتصل ليس متصفحاً؛ الحماية عبر **سر** في جسم JSON (`FAKE_*_WEBHOOK_SECRET`).
- في الإنتاج (`DEBUG=False`) ترفض الإعدادات القيم الافتراضية `dev-secret-*` — يجب تعيين أسرار من البيئة.
- تفاصيل النشر و Nginx للوسائط: [`DEPLOYMENT_NGINX.md`](DEPLOYMENT_NGINX.md).

## صيانة

- راقب السجلات للرسائل `security_services`.
- في الإنتاج: `DEBUG=False`، `SECRET_KEY` عشوائي قوي، بريد حقيقي لـ `EMAIL_BACKEND`.
